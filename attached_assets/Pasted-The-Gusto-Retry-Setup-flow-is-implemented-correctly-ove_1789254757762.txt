## Problem

The route:

```text
POST /api/operations/integrations/gusto/reconcile
```

currently returns:

```ts
{ status: "connected", ...result }
```

whenever capability reconciliation succeeds.

However, `reconcileConnectedProviderCapabilities()` intentionally preserves unrelated degraded states.

Example:

```text
connection.status = degraded
connection.lastError = "Payroll sync failed"
```

Capability reconciliation may succeed, but because the degraded condition is unrelated to capability setup, the database correctly remains:

```text
status = degraded
lastError = "Payroll sync failed"
```

The API must not return:

```json
{
  "status": "connected"
}
```

when the persisted connection is still degraded.

## Required fix

After capability reconciliation, return the actual resulting provider connection status.

Preferred implementation:

Update:

```ts
reconcileConnectedProviderCapabilities(...)
```

to return both:

* the reconciliation result
* the actual final connection state

For example:

```ts
{
  status: "connected" | "degraded",
  assigned: [...],
  alreadyOwned: [...],
  conflicts: [...],
  unavailable: [...]
}
```

or an equivalent typed structure.

Do not infer the status in the route.

The service should determine the actual persisted state after reconciliation.
